Ordner

FIREBASE
├── users/{uid}
│   ├── username, displayName, role, active
├── admin/system
│   ├── masterData       ← gleiches Dokument wird aktualisiert
│   │   ├── version
│   │   ├── updatedAt
│   │   └── auftraege[]
│   ├── conflicts/{conflictId}
│   └── audit/{eventId}
├── monteure/{uid}
│   ├── sync/data        ← gleiches Dokument wird aktualisiert
│   │   ├── version
│   │   └── updatedAt
│   └── rapporte/{RPT-ID}
└── config/system
    ├── schemaVersion
    └── updatedAt

RPT

rptId
ownerUid
accessUids[]
orderNumber       ← darf leer sein
orderSource       ← master | external | none
reference
status            ← in_bearbeitung | fertig | zusammengefuehrt
revision
rapportStateJson
createdAt / createdBy
updatedAt / updatedBy
deleted / deletedAt / deletedBy
mergedFrom[]

RPT-ID bleibt immer gleich, auch bei Auftrag-, Besitzer-, Status- oder Freigabeänderung.

Auftragsnummer

leer → orderSource: none
unbekannte Nummer → external
Admin bestätigt → master

Auftragsnummer kann jederzeit nachgetragen oder korrigiert werden.
RPT bleibt gleich.

Local + SYNC

LOCAL
├── syncVersion
├── masterVersion
├── aktive Rapporte / Cache
└── changeLog[]

SYNC:
Version prüfen
→ nur Änderungen übertragen
→ Firebase-Bestätigung
→ Version aktualisieren
→ ERST DANACH Log leeren

Bei Fehler/Internetabbruch bleibt das Log erhalten.

Versionen

syncVersion   = Benutzer-Sync
masterVersion = Master-Aufträge
revision      = einzelner RPT

KEINE neuen Versionsdokumente.
sync/data bleibt dasselbe Dokument:
1 → 2 → 3 → 4

Konflikt

Peter baseRevision 5
Max baseRevision 5
Peter SYNC → Firebase revision 6
Max SYNC → 5 ≠ 6
→ NICHT überschreiben
→ beide Änderungen sichern
→ Admin prüft Konflikt

Freigabe / Übergabe

Freigabe:
ownerUid: Peter
accessUids: [Peter, Max]
→ gleicher RPT, keine Kopie

Übergabe:
ownerUid wird Max
→ RPT-ID bleibt gleich

Admin hat Zugriff auf alle Rapporte.

Fertig / Cache

Arbeit fertig X
→ SYNC
→ Firebase bestätigt
→ fertiger RPT zentral gespeichert
→ lokale Kopie darf entfernt werden

Browser-Cache löschen ≠ Firebase löschen.
Nicht synchronisierte Arbeit darf nie automatisch entfernt werden.

Zusammenführen / Löschen

RPT-A + RPT-B → neuer RPT-C
mergedFrom: [RPT-A, RPT-B]
Originale bleiben erhalten.

Löschen zuerst nur:
deleted: true
→ Wiederherstellung möglich.

Betrieb

Tagsüber hauptsächlich LOCAL.
Empfehlung ca. 16:00 → einmal SYNC.
Zusätzlicher SYNC jederzeit möglich.

Keine Firebase-Abfrage bei jedem Klick,
Tippen, Seitenwechsel, Material suchen
oder lokalen Öffnen eines Rapports.
